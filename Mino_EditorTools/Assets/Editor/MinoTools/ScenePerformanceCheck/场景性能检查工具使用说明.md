# 场景性能检查工具使用说明

本文档用于指导你使用场景性能检查工具 `ScenePerformanceCheckWindow`。

## 1. 工具信息

- 脚本路径：`Assets/Editor/MinoTools/ScenePerformanceCheck/ScenePerformanceCheckWindow.cs`
- 菜单入口：`Tools/MinoTools/场景性能检查/场景性能检查工具`
- 依赖：独立工具，不调用其他 MinoTools；需 URP（`Volume` / `VolumeProfile`）以扫描后处理

### 主要能力

对**当前已打开并加载的场景**做一次性能向扫描，覆盖：

| 模块 | 扫描内容 |
|------|----------|
| 模型 | `MeshRenderer` / `SkinnedMeshRenderer` 面数、顶点、材质槽、骨骼、LOD |
| 贴图 | 场景内材质与 UI 实际引用的贴图（分辨率、Import Max Size、磁盘体积、引用次数） |
| 实时光照 | 非纯烘焙灯（Realtime / Mixed），含阴影开关与混合模式说明 |
| 后处理 | 场景中 `Volume` 及其 Profile 内已启用组件，标记高开销项 |

附加能力：

- 可配置阈值与是否包含非激活对象
- 分页查看汇总 / 模型 / 贴图 / 实时光 / 后处理
- 一键定位场景对象或 Project 贴图资源
- 导出 Markdown 报告（适合评审、提测归档）

### 与其他工具的区别

| 工具 | 扫描范围 | 侧重点 |
|------|----------|--------|
| **本工具** | 当前场景 | 场景级性能快照：总面数、场景引用贴图、实时光、Volume |
| 模型基础检测工具 | 指定节点或 Prefab | 单资产质量：重叠顶点、碰撞挂载、BlendShape、MeshCollider 等 |
| 贴图大小检测工具 | 整个项目目录 | 全项目贴图体积与分辨率，可按格式过滤 |

## 2. 使用流程

1. 在 Unity 中**打开并加载**需要检查的场景（必须是当前活动场景）。
2. 打开菜单：`Tools/MinoTools/场景性能检查/场景性能检查工具`。
3. 在窗口顶部配置 **扫描范围** 与 **阈值**（可按平台调整，见第 6 节建议）。
4. 点击 **「扫描当前场景」**，等待弹窗显示摘要。
5. 通过顶部 Tab 切换查看：**汇总**、**模型**、**贴图**、**实时光**、**后处理**。
6. 对问题项使用 **「定位对象」** 或 **「定位资源」** 在 Hierarchy / Project 中跳转。
7. 需要留档时，点击 **「导出 Markdown 报告」**，选择保存路径。
8. 重新检查其他场景前，可先 **「清空结果」** 或直接在另一场景再次扫描。

> **注意**：未保存的场景修改不会影响扫描逻辑，但报告中的场景路径以当前 `Scene` 资产路径为准；若场景未保存，路径可能为空。

## 3. 界面与参数说明

### 3.1 扫描范围

| 参数 | 说明 |
|------|------|
| 包含非激活对象 | 开启时遍历场景中 `activeInHierarchy == false` 的节点；关闭则跳过整棵未激活子树 |

### 3.2 阈值（可在窗口内直接修改）

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 单网格面数阈值 | `10000` | 单个 Mesh 三角面数超过该值 → 记入模型警戒，并在明细中标记 |
| 场景总面数警戒 | `300000` | 场景所有网格三角面之和超过该值 → 汇总页告警 |
| 材质槽位警戒 | `2` | 单个 Renderer 的 `sharedMaterials` 数量超过该值 → 记入模型警戒 |
| Skinned骨骼数警戒 | `80` | `SkinnedMeshRenderer` 骨骼数超过该值 → 记入模型警戒 |
| 贴图宽度阈值 | `2048` | 贴图宽度超过该值 → 记入贴图警戒 |
| 贴图高度阈值 | `2048` | 贴图高度超过该值 → 记入贴图警戒 |
| 贴图磁盘阈值(MB) | `2` | 源文件磁盘体积超过该值 → 记入贴图警戒 |
| 实时光数量警戒 | `4` | 实时光（见下文定义）总数超过该值 → 汇总 / 实时光 Tab 告警 |
| 投影灯光数量警戒 | `1` | 开启阴影的实时光数量超过该值 → 汇总 / 实时光 Tab 告警 |

### 3.3 操作按钮

| 按钮 | 说明 |
|------|------|
| 扫描当前场景 | 清空上次结果并重新扫描活动场景 |
| 清空结果 | 清除列表与统计，Tab 不再显示数据 |
| 导出 Markdown 报告 | 需先完成扫描；导出后会在资源管理器中Reveal 文件 |

## 4. 扫描逻辑说明

### 4.1 模型

- 遍历场景根节点下所有 Transform（受「包含非激活对象」影响）。
- 统计 `MeshFilter` + `MeshRenderer` 与 `SkinnedMeshRenderer`。
- 每个网格记录：层级路径、Mesh 名、Renderer 类型、三角面、顶点、材质槽数、骨骼数、父级链是否存在 `LODGroup`。
- **模型警戒** 满足以下任一即列入「超阈值 / 缺 LOD」：
  - 三角面 > **单网格面数阈值**
  - 材质槽 > **材质槽位警戒**
  - Skinned 骨骼数 > **Skinned骨骼数警戒**
  - 三角面 > **单网格面数阈值的一半** 且父级链上**没有** `LODGroup`（缺 LOD 预警）

列表按三角面数降序排列。

### 4.2 贴图

- 收集来源：
  - 场景内所有 `Renderer.sharedMaterials` 中，Shader 属性类型为 `TexEnv` 的贴图；
  - `UnityEngine.UI.Graphic` 的 `mainTexture`。
- 仅统计 **Project 内资产**（`AssetDatabase.GetAssetPath` 有效）；运行时生成、内置资源等无路径贴图不会出现在列表中。
- 同一资产路径合并为一条，**引用次数** 累加。
- **贴图警戒**：宽度或高度超阈值，或磁盘体积超阈值。
- 磁盘大小为源文件字节数（非 GPU 显存占用）。

### 4.3 实时光照

- **纳入**：`LightmapBakeType` 为 `Realtime` 或 `Mixed` 的灯光。
- **排除**：纯烘焙灯（`Baked`）。
- 统计投影光：`shadows != None` 的实时光数量。
- 每条记录包含：类型、Bake 模式、Mixed 模式、阴影模式、强度、范围及中文备注（完全实时光 / 混合光）。

### 4.4 后处理（URP Volume）

- 扫描带 `Volume` 组件的对象；Profile 优先取 `sharedProfile`，否则取 `profile`。
- 列出 Profile 中 **active == true** 的 `VolumeComponent` 类型名。
- **高开销组件**（工具内标记，优先关注）：
  - `Bloom`、`DepthOfField`、`MotionBlur`、`ScreenSpaceAmbientOcclusion`、`ScreenSpaceLensFlare`
- 另将多种调色类组件（如 `ColorAdjustments`、`Tonemapping` 等）纳入「开销相关」统计，用于 Volume 异常判定。
- **后处理警戒** 满足以下任一：
  - 存在至少一个高开销组件；
  - `weight > 0.01` 且启用组件数量 **> 6**。

## 5. 结果分页解读

### 5.1 汇总

- 场景名称与资产路径。
- 模型：Renderer 数量、总三角面 / 顶点、唯一材质数、材质槽合计、是否超场景总面数警戒。
- 贴图：贴图条数、磁盘总体积、超阈值条数。
- 实时光：数量、投影光数量、是否超两项灯光警戒。
- Volume：数量、高开销项计数、异常 Volume 数。
- **快速结论**：无问题时提示「未发现超过阈值的项」；否则显示需关注项总数（含场景总面数超警戒计为 1 类）。

Tab 标题括号内数字为对应分类的问题计数（汇总 Tab 为各类问题之和）。

### 5.2 模型

- **全部网格**：场景中所有有效网格条目。
- **超阈值 / 缺 LOD**：仅警戒项；单网格面数超阈值会显示 ⚠ 标记。
- 每条可 **定位对象**（选中并 Ping Hierarchy 节点）。

### 5.3 贴图

- 全部场景引用贴图，默认按磁盘体积降序。
- 路径旁 **⚠** 表示分辨率或体积超阈值。
- **定位资源**：在 Project 窗口选中并 Ping 贴图资产。

### 5.4 实时光

- 顶部 HelpBox：当实时光数或投影光数超警戒时显示警告。
- 清单为全部非纯烘焙灯，便于人工判断是否保留实时阴影。

### 5.5 后处理

- 列出每个 Volume 的 Global、Priority、Weight、Profile 路径、启用组件。
- **高开销** 行加粗显示，便于移动端或低端机关闭对应效果。

## 6. 阈值建议

### 移动端 / 低端机

| 参数 | 建议范围 |
|------|----------|
| 单网格面数阈值 | `3000 ~ 8000` |
| 场景总面数警戒 | `100000 ~ 200000` |
| 材质槽位警戒 | `1 ~ 2` |
| Skinned骨骼数警戒 | `50 ~ 80` |
| 贴图宽高阈值 | `1024` 或 `2048` |
| 贴图磁盘阈值(MB) | `1 ~ 2` |
| 实时光数量警戒 | `0 ~ 2` |
| 投影灯光数量警戒 | `0 ~ 1` |

### PC / 主机

| 参数 | 建议范围 |
|------|----------|
| 单网格面数阈值 | `10000 ~ 30000` |
| 场景总面数警戒 | `300000 ~ 800000` |
| 材质槽位警戒 | `2 ~ 4` |
| Skinned骨骼数警戒 | `80 ~ 120` |
| 贴图宽高阈值 | `2048 ~ 4096` |
| 贴图磁盘阈值(MB) | `2 ~ 8` |
| 实时光数量警戒 | `4 ~ 8` |
| 投影灯光数量警戒 | `1 ~ 3` |

可按项目画质档位保存多套阈值，扫描前在窗口内手动切换（当前版本阈值随 EditorWindow 序列化，关闭窗口后仍保留上次输入）。

## 7. Markdown 报告

导出文件默认命名：`ScenePerf_{场景名}_{yyyyMMdd_HHmmss}.md`

报告结构：

1. **汇总**：总面数、顶点、Renderer 统计、贴图总体积、实时光与 Volume 摘要  
2. **模型（超阈值 / 警戒）**：场景总面数超限说明 + 警戒网格列表  
3. **贴图（超阈值）**：仅超阈值贴图  
4. **实时光照**：全部实时光清单（非仅警戒）  
5. **后处理 Volume**：每个 Volume 的高开销项与启用组件列表  

适用场景：关卡提测、性能评审会议、外包场景验收附录。

## 8. 常见问题

### 点击扫描提示「请先打开并加载一个场景」

- 确认 Hierarchy 中有已加载场景，且为当前 **活动场景**（非仅 Prefab 模式、非空场景列表）。

### 贴图数量比预期少

- 工具只统计**当前场景引用**的贴图，不是全项目扫描。
- 无 `Assets/` 路径的贴图（默认材质、动态生成等）不会出现。
- 若材质在 Renderer 上但未挂到场景对象（仅 Prefab 资产内），需打开对应 Prefab 场景或使用贴图检测工具扫项目。

### 实时光数量为 0 但场景里有很多灯

- 灯光若全部为 **Baked**，会被排除；仅 Realtime / Mixed 计入。
- 检查 Light 组件的 **Mode**（Baked / Mixed / Realtime）。

### 后处理 Tab 为空

- 场景未放置 `Volume`，或未使用 URP 后处理栈。
- 非 URP 项目可能没有 `Volume` 组件，该 Tab 正常为空。

### 模型警戒很多但面数不高

- 可能是 **缺 LOD**（面数 > 单网格阈值的一半且无 LODGroup）或 **材质槽 / 骨骼** 超阈值，不一定是面数问题。

### 与模型检测工具如何配合

1. 本工具：关卡 / 场景整体过一遍，看总面数、场景贴图引用、灯光与后处理。  
2. 模型检测工具：对汇总里问题节点或 Prefab 做深度检测（重叠顶点、碰撞、BlendShape 等）。

## 9. 限制说明

- 仅支持 **Editor 下当前活动场景**，不支持批量多场景、不支持仅扫选中子树。
- 三角面通过 `mesh.triangles.Length / 3` 计算，与导入设置、Read/Write 有关；极高面数 Mesh 在 Editor 中可能略慢。
- 贴图磁盘大小为 **源文件** 大小，与运行时 ASTC/ETC 压缩后显存占用无直接对应关系。
- 后处理开销分级为工具内置类型名列表，实际 GPU 代价仍与分辨率、URP Asset、Renderer Feature 相关，需结合 Profiler 验证。
- 工具不修改场景或资产，仅只读扫描与导出报告。

## 10. 快速检查清单（提测前）

- [ ] 场景总面数是否低于项目警戒值  
- [ ] 「超阈值 / 缺 LOD」列表是否已处理或已说明  
- [ ] 超阈值贴图是否已降分辨率或拆分引用  
- [ ] 实时光与投影光数量是否符合目标平台预算  
- [ ] Volume 是否关闭不必要的高开销后处理（移动端尤其注意 SSAO、DOF、Motion Blur）  
- [ ] 已导出 Markdown 并附在单号 / 评审记录中
